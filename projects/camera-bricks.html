Camera Bricks

Transform any generic photo into a vibrant, eye-catching Brick picture.

Python Streamlit OpenCV Docker
Live Demo

Overview

Camera Bricks turns any photo into brick art. Upload an image, pick a brick shape, a level of detail and a colour palette, and the app rebuilds the picture as a mosaic of rendered studs, ready to download as a framed polaroid-style print.

The conversion is a small image-processing pipeline. The upload is first normalised to a fixed working width, then cropped so both dimensions are exact multiples of the brick grid — no partial bricks at the edges. Each cell of that grid is reduced to its average colour, and the average is matched to the nearest entry in the chosen palette using a distance weighted 0.3 / 0.59 / 0.11 across R, G and B rather than a plain Euclidean one, so the match follows perceived brightness instead of raw channel difference.

The last step is what makes the result read as plastic rather than as large pixels: instead of filling each cell with flat colour, the matched colour is multiplied onto a real greyscale photograph of a brick. The stud's own highlights and shadows survive the tinting, so every one of the thousands of tiles in the mosaic keeps its moulded, three-dimensional look.

It runs as a Streamlit app — the entire interface, from the uploader to the download button, is defined in the same Python codebase that does the imaging, with no separate front end to build or deploy.

How the conversion works

  • Normalise — the uploaded photo is resized to a fixed 96-pixel working width with its aspect ratio preserved, which bounds the cost of the conversion no matter how large the original file is. Greyscale and RGBA uploads are coerced to three-channel RGB first.
  • Crop to the grid — the brick size in source pixels is derived from the requested horizontal brick count, and the image is trimmed to an exact multiple of it. At 24 bricks each tile averages a 4×4 block, at 48 a 2×2 block, and at 96 the grid lines up one-to-one with the working pixels.
  • Average and match — each block is reduced to its mean colour per channel, then scored against every colour in the selected palette with the luminance-weighted distance; the closest one wins.
  • Render the brick — the matched colour is multiplied onto the greyscale texture of the selected brick shape and clipped back into range, producing a 30×30-pixel tile that keeps the original stud's shading.
  • Compose — the tiles are written into the output canvas at 30 pixels each, so a 96-brick-wide render comes out nearly 3,000 pixels across — large enough to print.
  • Frame — a polaroid treatment adds a white border with a deep bottom band and a thin black outline, then centres the Camera Bricks logo in the band. The unframed mosaic is shown on screen with its brick dimensions, and the framed version is what the download button returns.

Key features

  • 14 colour palettes — the classic brick set, black & white, five monochrome scales, three Warhol-style art palettes and three limited sets of 10, 20 and 75 colours. Each is a plain CSV of names and RGB triples, so adding a palette is a file rather than a code change.
  • 4 brick shapes — round or square studs, each in a raised or flat variant, with a 3D preview of the selected brick shown next to the control so the choice is visible before generating.
  • 3 detail levels — 24, 48 or 96 bricks across, trading the chunky look of a small build against the fidelity of a large one.
  • Brick count readout — the result is labelled with the mosaic's horizontal and vertical brick counts, which doubles as an estimate of how big a physical build would be.
  • Polaroid download — the framed, logo-stamped render is offered as a JPEG straight from the browser, with no file ever written to the server's disk.
  • Example gallery — a dedicated tab with 24 sample transformations, laid out in mixed-width rows so portraits and landscapes both sit well.
  • Cached asset loading — palettes, brick textures and static images are memoised with a one-hour TTL, so repeated renders and page reruns don't re-read the same files.
  • Custom-skinned Streamlit — injected CSS hides the default menu, header, footer and fullscreen affordances and constrains the content width, so the app reads as a product rather than as a notebook UI.
  • Full legal footer — a GDPR-oriented terms, conditions and privacy policy section, plus support contact links and a Buy Me a Coffee tab.

Tech stack

Python

Holds the whole application in two modules: lego_app.py for the page layout and flow, and functions.py for the imaging helpers — cropping, nearest-colour matching, brick colourisation, framing and the download plumbing.

Streamlit

Provides the entire interface — file uploader, the brick / size / palette selectors, tabbed navigation, spinners and download buttons — from the same Python file as the logic. Its cache_data decorator memoises the palette and asset loaders, and the app is configured for a wide layout, a collapsed sidebar and a 20 MB upload limit.

NumPy & pandas

NumPy carries the pixel work: block averaging, the tinting of the brick texture, clipping back into 8-bit range and writing each tile into the output canvas. pandas parses the palette CSVs into the name/RGB mapping the matcher consumes.

OpenCV & Pillow

OpenCV builds the polaroid frame with copyMakeBorder, using an asymmetric bottom border plus a thin black outline. Pillow handles decoding, resampling, the logo composite with alpha masking, and encoding the final JPEG into the in-memory buffer the download button serves.
