Cosmos - Web Application

Multi AI Agent

Python Javascript React FastAPI Ollama LM Studio OpenAI LLM

Overview

Cosmos is a fully local, single-user dashboard for orchestrating a team of specialized AI agents through one conversational interface. There is no login, no external account, and no cloud database: every agent's configuration, chat history, and personal data stay on the machine running the app.

Each agent is defined declaratively by a config.json — its own role, system prompt, skills, and LLM provider — and is discovered automatically at backend startup by scanning the agents folder. Adding a new agent never requires touching the core application code, just dropping in a new config file.

An orchestrator agent, Jarvis, sits in front of the team: it breaks down a user's request, delegates the relevant parts to the right specialist agents, collects their results, and synthesizes a single answer. The backend is built with FastAPI and streams responses token-by-token over WebSocket, while the React + Vite + Tailwind front end renders the chat, calendar, routines, and agent-configuration views.

Key features

  • Multi-agent orchestration. Jarvis decomposes a request and delegates sub-tasks to specialized agents (calendar, email, web search, copywriting, math) via a delegate_to_agent tool, then merges their results into one coherent reply.
  • Unified LLM provider layer. The same interface talks to LM Studio, Ollama, OpenAI, and Anthropic (Claude) — the provider, model, endpoint, and API key can be swapped per agent live from the UI, with a one-click connection check, no backend restart needed.
  • Tool-calling with a textual fallback. Agents can invoke skills even on local models without native function-calling: a tool_mode setting falls back to a TOOL_CALL: {json} text protocol that the backend parses transparently, hiding the raw syntax from the user-visible stream.
  • Real-time streaming chat. Responses stream over WebSocket with stop/resume controls and a live "agents at work" indicator while the orchestrator's sub-agents are running.
  • Scheduled routines. Any agent can be set to run automatically on an interval or a daily/weekly schedule (or triggered manually), with results saved for later reference — e.g. a daily LinkedIn post draft or a morning inbox summary.
  • Morning briefing and job queue. An automatic daily briefing aggregates the day ahead, and a per-agent job queue tracks routine runs and their outcomes.
  • Google Calendar, Tasks, and Gmail integration. Two agents (Alex and Emma) act on the user's real Google account through OAuth, always asking for explicit confirmation before any destructive or outbound action (sending an email, deleting an event).
  • Ephemeral sessions. Chat history lives in memory and can be cleared with a single click — nothing persists beyond what the user explicitly wants kept.

Tech stack

Python

Backend language. Powers the agent loader, orchestrator, tool registry, and Google API integrations.

FastAPI

Serves the REST endpoints and the WebSocket chat stream, with Uvicorn as the ASGI server and auto-generated Swagger docs.

React

Builds the dashboard, agent cards, chat panels, calendar, and routines views as a single-page front end.

Javascript

Drives the Vite-powered front end tooling and the client-side logic connecting UI state to the streaming API.

Ollama

One of the supported local LLM providers, used to run open-weight models entirely on-device with no external calls.

LM Studio

Default local provider: exposes downloaded models through an OpenAI-compatible endpoint that the agents talk to out of the box.

OpenAI

Supported as a cloud provider (or any OpenAI-compatible endpoint), selectable per agent alongside the local options.

LLM

The core abstraction behind every agent: a unified provider interface lets each agent's model, temperature, and tool-calling mode be configured independently.
