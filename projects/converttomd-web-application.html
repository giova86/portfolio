ConvertToMD - Web Application

A fully local web application that converts PDF, DOCX, DOC, XLSX, and XLS files into Markdown.

Python FastAPI React HTML Ollama LLM

Overview

ConvertToMD converts PDF, DOCX, DOC, XLSX, and XLS files into clean, well-structured Markdown, entirely on the user's own machine — no document is ever uploaded to an external service. It offers two conversion paths depending on the format: a direct mode that parses DOCX and XLSX structurally with python-docx and openpyxl, and an OCR mode that renders each page as an image and asks a locally-hosted vision-language model to transcribe it into Markdown. PDFs and the legacy DOC/XLS formats — which have no reliable structural parser — always go through OCR; DOC and XLS files are first bridged to PDF with a headless LibreOffice conversion.

The web app is a React front end with a split-view editor: the original page renders on one side, its Markdown output on the other, so every page can be inspected and re-run individually before the file is downloaded. The OCR back end isn't hard-wired to Ollama — a small backend abstraction lets the app talk to Ollama, LM Studio, or any vLLM server that speaks the OpenAI chat-completions API, so the vision model doing the transcription can be swapped without touching the app's logic. A separate CLI script (scripts/convert.py) exposes the same conversion pipeline for batch-processing a whole folder of documents without opening the browser at all.

Key features

  • Split-view conversion — the rendered document page sits next to its Markdown output, with a toggle between a rendered preview and the raw Markdown source, so formatting can be checked page by page as it's produced.
  • Per-page or one-click OCR — each page can be converted individually, or the whole document can be queued with "OCR all," which skips pages already marked done so a run can be resumed after an interruption.
  • Direct structural extraction for DOCX/XLSX — Word documents keep their heading levels, bold/italic runs and tables; Excel workbooks are walked sheet by sheet into Markdown tables. Both are deterministic and don't touch the OCR model at all.
  • Pluggable local LLM backend — a settings panel lets the OCR server be pointed at Ollama, LM Studio, or vLLM, with a "test connection" step that lists the models actually available on that server before one is picked as default.
  • Per-page model override — the model used for OCR can be changed page by page, useful for re-running a page that came out garbled with a different model without restarting the whole document.
  • Download as Markdown — the direct-mode result or the combined per-page OCR output downloads as a single .md file, generated client-side with no round trip to the server.
  • Dark mode — the whole interface, including the split-view editor and settings modal, has a dark theme toggle.
  • CLI batch converter — scripts/convert.py processes an entire input folder to Markdown outside the browser, with flags for the conversion mode, render DPI, OCR model, Ollama endpoint, and per-page timeout, and skips files it has already converted unless --force is passed.
  • 100% local — no file leaves the machine and no API key is required by default; the OCR step runs entirely against a locally-hosted model server.

Tech stack

Python

Backend language for the FastAPI service, the DOCX/XLSX converters, and the standalone CLI batch script.

FastAPI

Exposes the REST API — upload, direct conversion, PDF bridging, per-page OCR, and settings/model endpoints — consumed by the React front end.

React

Drives the whole interface: the upload zone, the mode-selection step, the split-view editor with its page strip and model picker, and the settings modal — built with Vite and Tailwind CSS.

HTML

Markup foundation for the app shell and the Vite-built static output served to the browser.

Ollama

Default local model server for the OCR path — runs the vision-language model that turns a rendered page image into Markdown, with no data leaving the machine.

LLM

A vision-language model (glm-ocr by default) reads each rendered page image and returns structured Markdown — headings, tables, lists — through a backend-agnostic interface that also supports LM Studio and vLLM.
