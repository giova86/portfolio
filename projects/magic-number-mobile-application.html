Magic Number - Mobile Application

A mind-reading card trick reimagined as a Flutter app: swipe six cards, shake the phone, and watch it reveal the number you were only ever thinking of.

Dart Flutter

Overview

Magic Number is a Flutter implementation of a classic mentalist card trick, not a number-guessing game. The player picks any number from 1 to 63 and keeps it secret. The app deals a shuffled stack of six cards — labelled 1, 2, 4, 8, 16 and 32 — one at a time. For each card, the player swipes up if their number appears on it, or down if it doesn't. Once all six cards have been answered, they shake the phone, and the app reveals the exact number they were thinking of.

The trick works because each card encodes one bit of the number's binary representation: card N shows every number whose binary form has bit N set. Summing the values of only the cards the player swiped "yes" on reconstructs the original number — classic binary encoding, dressed up as a magic trick. The app doesn't need to know the number in advance; it only needs the player's six yes/no answers, and it recomputes the total live as each card is dismissed.

It's a small, self-contained single-screen Flutter app: one StatefulWidget drives the shuffled card deck, the swipe-to-dismiss interactions, the phone-shake reveal (via the device accelerometer), and a floating reset button to deal a fresh, re-shuffled stack.

Key features

  • Binary-encoding card trick: six cards (values 1, 2, 4, 8, 16, 32) each list every number from 1–63 that has that bit set in its binary representation, so the sum of the cards the player confirms always reconstructs their secret number.
  • Freshly shuffled deck every round: the six cards are reshuffled with List.shuffle on each new game, so the reveal never happens in the same, memorizable card order twice.
  • Vertical swipe-to-dismiss gameplay built on Flutter's Dismissible: swipe a card up if the secret number is on it (adds its value to the running total), swipe down to discard it with no effect, both with a 20%-of-height dismiss threshold.
  • Messy, tactile card-stack presentation: each card gets a small randomized rotation and x/y offset so the stack looks hand-scattered rather than perfectly aligned, with drop shadows for depth.
  • Dismissible instructions overlay: an in-stack "ISTRUZIONI" card explains the rules in Italian and fades out (via an AnimationController/Tween) on first tap, so it only ever gets in the way once.
  • Shake-to-reveal result screen: once every card is gone, the sensors_plus accelerometer stream watches for a shake gesture past a magnitude threshold, accumulating "shake energy" that fades the answer in from fully transparent to solid white as the player keeps shaking.
  • One-tap reset via a floating action button that re-shuffles the deck, restores the instructions card, and zeroes the running total and shake progress, so a new round can start immediately.
  • Locked portrait orientation with immersive/edge-to-edge system UI, including a small platform channel that detects Android's navigation mode (gesture vs. button bar) to pick the right system UI overlay mode.

Tech stack

Dart

Implements the whole game as a single StatefulWidget: the shuffle-and-deal logic, per-card swipe handling and running-total bookkeeping, the accelerometer-driven shake accumulator that maps raw sensor magnitude to a 0–1 reveal progress, and the fade animations for the instructions card, all with plain dart:math and dart:async — no external state-management package.

Flutter

Renders the scattered card stack with Stack/Positioned/ Transform.rotate, handles swipe gestures through Dismissible with custom vertical dismiss thresholds, and drives the instructions fade-out and shake-reveal opacity with AnimationController. A native MethodChannel queries the Android navigation-bar mode at startup to choose the correct SystemUiMode.

sensors_plus

Streams live accelerometer events used to detect the "shake to reveal" gesture: the app sums the vector magnitude of each event, and once it clears a threshold accumulates that excess into a progress value that controls how visible the revealed number becomes.
